# Content Tracking Dashboard — Project Instructions

## Overview
Personal media analytics dashboard: analyzes ~370 titles (movies/series) logged in a Google Sheet. Frontend is a vanilla JS SPA; Netlify functions talk straight to the Google Sheets API with a service-account key. There is **no Apps Script** anywhere — nothing to redeploy by hand.

## Tech Stack
- Frontend: `index.html` (static shell + nav) + `app.js` (SPA that renders every page from the Sheet API) + `styles.css`
- Charts: Chart.js 4.4.1 (CDN, loaded on every page even though only Current Year / All Time use it)
- Backend: `netlify/functions/` — `watchlist.js` (data + goal read), `goal.js`, `suggestions.js`, `admin-login.js`, `admin-entry.js` (create/update/delete), `tmdb-search.js` (TMDB search + OMDb rating/imdbId), `calendar.js` (release calendar: TMDB films + TVmaze episodes), shared code in `netlify/functions/lib/` (`sheets.js`, `throttle.js`)
- Release data: TMDB (`TMDB_API_KEY`, already configured on Netlify) for films, **TVmaze** for episodes — a free public API that needs no key at all. Nothing new has to be configured for the Calendar page on the deployed site, but the key is per **environment**: Netlify holds a value per deploy context (production / branch deploys / deploy previews / local development) and a value set for production only is absent everywhere else, so `calendar.js` reads the key per request and its warning **names the environment it was missing from** (`CONTEXT`, or "no Netlify context — local run"). A local function runner has no Netlify environment at all unless it is given one, which is why a locally served Calendar can be film-less while production is fine.
- Hosting: Netlify; dark mode persisted in `localStorage` (`ct-theme`)

## Files
```
index.html   → static shell: loading screen, nav tabs (Readme/Current Year/All Time/Data/Timeline/Calendar/Random Pick/Submit), theme toggle
app.js       → SPA: data fetch + all page/template rendering (uses many emojis as decorative icons)
styles.css   → design tokens in :root + html.dark; responsive blocks at ≤900px and ≤600px
netlify/functions/    → the API listed above
```

## Code Style / Conventions
- Nav tabs carry inline 13px SVGs declared in `index.html`; the brand mark is an inline TV SVG. On ≤900px the tab icons are hidden and `.nav-tabs` becomes a scrolling strip with a mask fade — the single-row nav is wider than the viewport between 601px and ~850px otherwise.
- `--nav-h` must match the **measured** nav height at each breakpoint (60px desktop, 73px mobile) — the sticky table header, timeline jump bar and month headers all offset from it.
- The theme toggle shows two SVGs (`.icon-sun`/`.icon-moon`) toggled by `app.js`; **do not** switch it back to `textContent = '🌙'/'☀️'`.
- The app body uses many emojis as icons (media-type emojis, insight rows, poster placeholders). Standardizing onto a real icon library is a known, feasible refactor — be careful: `app.js` frequently rewrites these nodes.
- "Recently Watched" cards, the Data table and the Random Pick result all pull real posters through the shared `MEDIA_CACHE` / `loadPoster` / `loadVisiblePosters` path; the emoji fallback is only for titles the media API can't resolve, and it swaps the `<img>` for a `<span class="… placeholder">`.
- **Display-level normalization only** — the Sheet keeps whatever was typed. `GENRE_MAP`/`TYPE_MAP`/`smartCaseName` in `app.js` merge near-duplicate labels ("Science Fiction" → "Sci-Fi", "Series/Show" → "Series") and capitalise all-lowercase titles at render time.
- Year-over-year figures compare **the same months** on both sides (`Jan–Sep 2026` vs `Jan–Sep 2025`), skipping a month that is still running; the full previous year appears as context only. Don't reintroduce year-to-date vs full-year comparisons.
- Ratings come from the on-demand media lookup and are cached per device: the Data page shows coverage and offers "Load all ratings" (concurrency 3), and `buildDataCSV` falls back to `cachedRating()` so the export isn't limited to rows on screen.
- `ct-media-cache` stores `{ items, miss }`. A title the media API answers **without a rating** is recorded in `miss` (7-day TTL, `MEDIA_MISS_TTL`), because such a title never gains an `imdbId` and would otherwise be re-queried — TMDB *and* OMDb — on every single re-render. `ratingCoverage().dead` counts those as "unavailable" so the coverage readout and the "Load all ratings" button can actually finish; a later success clears the marker.
- The Data table's `<th>`s are keyboard-sortable (`tabindex`/`aria-sort`/`title`); sort state lives in `sortDataBy()`, which also restores focus to the same header (the re-render throws the element away). `dataVal()` must return `''` for a missing value — `compareData()` sinks empty values to the bottom, but a numeric `0` is not empty, so returning 0 for a missing episode count / rating buried the 92 movies (or every unrated row) at the top of an ascending sort.
- `#dat-table` owns the horizontal scrollport at ≤900px too, not just ≤600px: the 9-column table is ~915px wide, so between 601px and ~950px the body's `overflow-x: hidden` used to clip the Rating / Watch Date columns with no way to reach them. The sticky header therefore only sticks where the table fits without scrolling (≥951px).
- Every `history.replaceState` writes `location.pathname` before the query. A **fragment-only** URL (`'#data'`) keeps the *current* query string, which left cleared filters in the address bar and let `applyDataFilters()` resurrect them on the next render — and left a one-shot `?fresh=` marker behind.
- **Never put `overflow: hidden` back on `table`** — it traps the sticky header/name cells in a box that never scrolls. The rounded corners are painted per-cell instead (thead th first/last, last row's first/last td).
- Timeline: `bindTimelineNav()` wires the year jump bar and the per-month expanders; long months render collapsed after 5 items.
- Adding a title through the Admin form is **gated by a duplicate check before any request is sent** (`submitAdminEntry()` → `adminDuplicateCheck()`), matching on the same keys the Duplicate Checker uses — `dupNormTitle`/`dupKind`/`dupSeasonKey`/`dupDateKey`, so "S2"/"Season 2"/"2" agree, casing never hides a match and a movie never collides with a same-named series. An exact repeat (same watch date *and* screentime) is refused with no way through; the same title+season on another date stops too but offers "Add anyway", the deliberate rewatch override — the same call the Duplicate Checker makes when it lists these as review-only. The gate fetches the sheet when it has not been read yet and **stops the add if it still cannot be read**, rather than writing unchecked; use `loadData(true)` there so the repaint cannot wipe the form. The server-side `findDuplicateRow` stays as the last-resort guard against a double submit.
- Data loads from the deployed functions at runtime, so a bare static server serves the shell but returns 404 for data — expected without the backend.
- The **Release Calendar** is the one page whose data does not come from the Sheet. Films come from TMDB `/discover/movie` (a release-date window in one region, plus one `with_watch_providers` sweep per top regional service so a streaming title gets a platform badge), episodes from TVmaze `/schedule/full`. It must be that TVmaze endpoint: the plain `/schedule` one excludes "episodes from global Web Channels like Netflix", i.e. exactly the half a release calendar is for, and `/schedule/full` answers with every future episode in a single ~3.3 MB request. TMDB cannot serve a calendar of episodes at all — its TV discover answers with *shows* that have an episode in the window — so this split is deliberate, not incidental. Both halves are best-effort: if one source fails the other still renders and the response carries `warnings` the page shows.
- `_headers` must keep `https://static.tvmaze.com` in `img-src`. The episode half of the calendar paints TVmaze posters; without that host they silently fall back to the emoji placeholder and read as missing data (same trap the note above the CSP block describes for `image.tmdb.org`).
- The calendar defaults to **premieres + films**, not everything: once daily news and talk shows count, TVmaze lists ~300 entries a day. The Show select's third option, **Episode releases**, is the readable middle — every episode of every show on its release day, with the films and the strips that air daily left out. Those strips are detected in `calIndex` rather than named: a title TVmaze calls news/talk, or one whose episodes land on more than a third of the window's days (`CAL_DAILY_FLOOR` is the floor, so a one-day window cannot flag everything; a fixed count would flag every weekly show across a year). A premiere, or any search query, bypasses the rule — typing the title *is* the request for it — and `calSyncTypeSelect()` disables the Type select's "Films only" option while the scope is on, because the pair can only ever paint an empty month. "Everything" is one select away, and the day drawer lists the whole day with sticky tier headings and a "Show all N" button that ignores the page filters for that day. Counts read as what is actually in the view (`calCountParts`): no "0 films" beside episodes, and the zeros only when nothing matched. Past days of the current month are dimmed and deliberately empty — it is a release calendar, not a history page.
- The calendar **rolls on the clock**: `calYearMonths()` is every month from the current one to December (a month that has ended can only be empty, so it is never offered), the two scope tabs carry the current and next year, and nothing in that chain is fixed at build time. The **window is the view**: this year asks for one month at a time (the current month from today, a later month whole) and next year asks for the whole year in one request — a different kind of window, which is why the two scopes are separate windows rather than one long one. Loaded windows are cached by `from|to|region` in `calState.cache` (max 4, pruned when the clock makes an entry obsolete), so moving between months repaints instead of refetching, and a stale copy paints immediately while the refresh lands behind it. `calScopeWindow()` is the single definition of "what am I asking for" — add a scope there, not at a call site.
- Auto-update is `calStartAuto()`/`calStopAuto()`: a minute tick (`calTick`) notices midnight and rolls the page forward — today's marker moves, the ended month leaves the strip, 1 January rolls both year tabs — and a 20-minute poll refetches the open window while the tab is visible (`visibilitychange` covers the rest). Timers are torn down in `navigateTo()`, so they cannot accumulate or keep polling from a page nobody is looking at. A *failed background* refresh keeps the window on screen and says so in `calState.notice`; only a failure with nothing to paint becomes an error state. **Refresh** stays the CDN-bypassing `?fresh=` load: the poll reads the CDN's 15-minute copy.
- The function's film window is sized by its own length (`moviePlan`): up to 100 days it is fetched in release-date order, page count scaled to the window (31 days → 4 pages, 61 → 8, capped at 8), because a calendar has to be complete; beyond that it switches to popularity order with 3 pages, because eight date-ordered pages of a year only reach its first weeks and a year-at-a-glance is about the films people will hear about. `MAX_DAYS` (400) is what lets the year window through at all — lowering it back under 366 silently truncates next year.
- `calState.platformsKey` is an options cache for the platform `<select>`. **Both `renderCalendar()` and `calAdopt()` must clear it**, because the page render (and every newly painted window) writes a fresh `<select>` holding only "All platforms": without the reset `updateCalendar()` decides the list is already current and leaves the dropdown empty for the rest of the visit. `calMatches()` also treats an empty platform value as `all`, since a select with no options reads back as `''`.
- Twelve month tabs cannot be one row on a phone: the strip **wraps** at ≤900px (a hidden month is a month nobody finds) and scrolls at ≤600px, where `updateCalendar()` scrolls the active tab back into view — the strip keeps its own scroll position across a rebuild otherwise.
- Calendar cell meta (premiere tags + platform) is hidden at ≤900px. Seven columns are ~73px wide at 601px and a nowrap "Series premiere" tag is 81px — it pushed the whole document sideways. Phones get the agenda instead of the grid (≤600px), which keeps its meta and skips empty days; the drawer keeps full detail at every width.
- The calendar response is cached `max-age=900` at the CDN and repainted from the in-page window cache. **Refresh** passes `?fresh=<timestamp>`, a URL the CDN has never seen — the same one-shot marker convention `reloadFresh()` uses after an admin write. The background poll deliberately does *not* pass it (it is meant to read the CDN copy), so a first visit that lands while TMDB is down can keep a film-less calendar for up to 15 minutes unless Refresh is pressed — which is why the partial-load warning is shown rather than swallowed.
- Calendar markup from the two APIs is escaped like any Sheet value (`escapeHTML` on titles, platforms, episode names and genres), and item links only survive `calSafeUrl()` (http/https).

## Build & Run
- No build step and no `package.json`: the repo root is the publish directory.
- Serve the folder statically for shell-only work; to exercise real data locally, use a tiny static server that proxies `/.netlify/functions/*` to the deployed site (and delete it afterwards — it is not part of the project).
- Deploys are Netlify; the functions and the static shell ship together from `main`.

## Git
- Work on `main`; imperative one-line commit messages.  Be careful to stage only intended files — this repo has had unrelated in-progress working-tree edits.
